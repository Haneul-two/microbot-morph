# microbot-morph — 설계 문서

작성일: 2026-09-19

## 개요

빅 히어로 6의 마이크로봇 장면에서 영감을 받은 웹 사이트. 수만 개의 입자가
프리셋 3D 형상들 사이를 오가며 재조립되고, **그 변형 과정 자체가 눈에 보이도록**
연출하는 것이 목표다.

## 확정된 요구사항

| 항목 | 결정 |
|---|---|
| 형상 소스 | 프리셋 갤러리 (사용자 업로드·텍스트 입력 없음) |
| 형상 생성 | 전부 코드(수식) 생성. 외부 에셋 0개 |
| 변형 연출 | 군집 비행 + 조립식 + 스크러버 **3종 모두** |
| 상호작용 | 커서 반발 + 복귀, 드래그 궤도 회전, 휠 줌 |
| 비주얼 톤 | 영화 재현 — 검은 금속 마이크로봇, 냉광 림라이트, 주황 액센트 |

## 채택한 접근: 셰이더 보간

입자마다 출발 좌표 A와 도착 좌표 B를 GPU 속성으로 올려두고, 매 프레임
진행률 `uT` 하나만 uniform으로 넘긴다. 위치 계산은 전부 vertex shader가 한다.

**채택 이유**: 상태가 누적되지 않으므로 스크러버(0~100% 자유 되감기)가
`uT`를 슬라이더에 연결하는 것만으로 구현된다.

**기각한 대안 — GPGPU 물리 시뮬레이션**: 텍스처에 위치를 저장하고 속도를
실제로 적분하면 100만 입자와 진짜 무리 행동이 가능하지만, 상태가 누적되기
때문에 되감기가 구조적으로 불가능하다. 요구사항과 충돌한다.

## 구조

```
index.html        importmap, 캔버스, UI 마크업, 스타일
src/shapes.js     형상 생성기 (순수 함수, three.js 비의존 → Node에서 테스트 가능)
src/delayModes.js '군집 비행' / '조립식' 시차 함수
src/particles.js  Points 지오메트리 + 커스텀 셰이더
src/morph.js      전이 상태 + 큐 + 자동 순회
src/postfx.js     잔상 누적 및 합성 패스
src/controls.js   자체 구현 궤도 카메라 (three 애드온 비의존)
src/pointer.js    커서 반발 스프링
src/ui.js         갤러리 버튼 · 모드 토글 · 스크러버
src/main.js       씬 조립 및 렌더 루프
```

three.js 코어만 CDN에서 가져온다. OrbitControls·EffectComposer 같은
`examples/jsm` 애드온은 CDN 제공이 불안정하므로 직접 구현한다.

## 형상 갤러리 (10종)

구 · 토러스 · 토러스 매듭 · 나선계단 · 아치형 다리 · DNA 이중나선 ·
큐브 격자 · 물결면 · 회오리 · 가시 구체

**불변 규칙**: 모든 형상이 정확히 같은 개수(기본 65,536)의 점을 반환한다.
입자 i가 형상 A의 i번째 자리에서 형상 B의 i번째 자리로 1:1 대응되어야 하기
때문이다.

**후처리 파이프라인** (모든 형상 공통):
1. bbox 중심으로 이동 → 형상마다 회전축이 어긋나지 않게
2. 최대 반경 1.5로 정규화 → 형상마다 화면 크기가 들쭉날쭉하지 않게
3. Morton code(3D z-order) 정렬 → 두 형상에서 가까운 인덱스가 공간적으로도
   가깝게 배치된다. 입자의 이동 거리가 짧아지고 이웃 관계가 유지되어 재조립이
   뭉개지지 않는다.

난수는 형상마다 고정 시드의 mulberry32를 쓴다. 같은 형상은 항상 같은 점
배치를 내놓아야 테스트가 안정적이다.

## 변형이 "보이게" 만드는 장치

| 장치 | 구현 | 효과 |
|---|---|---|
| 입자별 시차 `aDelay` | 국소 진행률 `p = (uT - aDelay) / (1 - aDelay)` | 동시에 안 움직여서 흐름이 생김 |
| 바깥으로 부푸는 궤적 | 중심 반대 방향으로 `sin(p·π)` 만큼 이탈 | 순간이동이 아니라 "날아간다"로 읽힘 |
| Y축 소용돌이 | 입자 시드별로 다른 각도로 회전 | 휘감기는 난류 |
| 사인 기반 난류 | 축을 엇갈린 사인 합성, 양 끝에서 0으로 수렴 | 비행 중 흐트러짐 |
| 속도 연동 발광·잔상 | 셰이더에서 `pathAt(t) - pathAt(t-dt)` 로 속도 추정 | 빠른 입자일수록 밝고 꼬리가 김 |

난류에 `sin(p·π)` 를 곱하는 이유: 양 끝(p=0, p=1)에서 정확히 0이 되어야
출발·도착 형상이 흐트러지지 않고 또렷하게 맺힌다.

**3단계 상태머신**은 별도 엔진이 아니라 위 파라미터들의 시간 포락선이다.
해체(0~25%) → 비행(25~80%) → 재조립(80~100%).

**조립식 모드**는 시차 함수만 "목표 Y가 낮은 순서"로 바꾼 것이다. 별도
코드 경로가 아니다.

## 상호작용

- **커서 반발**: 커서가 만드는 시선 광선까지의 수직 거리로 판정한다. 광선을
  축으로 하는 원기둥 안의 입자가 축에서 멀어지는 방향으로 밀린다. 변위는
  CPU의 스프링 버퍼에 누적되어 `aDisp` 속성으로 올라가고, 커서가 떠나면
  감쇠로 제자리에 돌아온다.
- **왜 점이 아니라 광선인가** (구현 중 수정): 처음에는 커서를 원점을 지나는
  카메라 정면 평면의 한 점으로 투영했다. 형상이 대부분 속이 빈 껍질이라
  그 점이 껍질 안쪽 빈 공간에 놓였고, 반경 안에 입자가 하나도 들어오지
  않아 반발이 거의 보이지 않았다. 광선 거리로 바꾸니 화면에서 커서와 겹쳐
  보이는 입자가 깊이와 무관하게 반응한다.
- **계산 기준점**: 반발 거리 판정은 입자의 *정착 좌표*(현재 형상 배열)를 쓴다.
  셰이더가 계산하는 비행 중 실시간 좌표를 CPU에서 다시 구하려면 경로 수식을
  이중으로 유지해야 하는데, 그 중복이 버그의 원인이 된다. 사용자가 입자를
  만지는 순간은 대개 형상이 정착한 상태이므로 실질적 차이가 없다.
- **업로드 절약**: 변위 에너지가 0이면 속성 업로드를 건너뛴다.
- 드래그 궤도 회전, 휠/핀치 줌, 터치 지원.

## 잔상 (postfx)

화면 전체 피드백 방식. `rtScene` → 밝은 부분만 추출해 이전 누적 버퍼와
`max(bright, prev * decay)` 로 합성 → 최종 합성 시 원본에 더한다.

**알려진 트레이드오프**: 화면 공간 누적이므로 카메라를 돌리면 화면이 번진다.
궤도 회전 중에는 decay를 0.93 → 0.75로 낮춰 완화한다.

## 전이 중 형상 전환

전이가 진행 중일 때 다른 형상 버튼을 누르면 **큐에 넣고** 현재 전이가 끝난
뒤 이어서 실행한다. 버튼에 대기 표시가 뜬다.

전이 중간 좌표에서 곧바로 새 전이를 시작하려면 셰이더의 경로 수식을 JS에
복제해야 한다. 두 벌을 동기화하는 비용이 얻는 것보다 크다고 판단했다.

**정착 판정** (구현 중 수정): 정착은 "재생으로 끝났는가"가 아니라 "t가 끝에
닿았는가"로 판정한다. 처음에는 재생 완료 시에만 정착시켰는데, 스크러버를
100%까지 밀면 `currentId`가 갱신되지 않아 대기 중인 형상이 영영 실행되지
않고 이후 선택도 먹지 않는 상태로 굳었다.

## 2차 추가 (관람자 반응 개선)

초기 구현을 보고 나서, 처음 보는 사람의 반응을 기준으로 세 가지를 더했다.

### 오프닝 시퀀스

**문제**: 페이지를 열면 정착한 구가 가만히 떠 있고 2.6초 동안 아무 일도
없었다. 방문자는 그 전에 판단을 끝낸다.

**구현**: `buildScatter()`가 만든 흩어진 구름을 출발점으로 첫 형상을
조립한다. 갤러리에 넣지 않는다 — 사용자가 고를 형상이 아니다.
`fromId === toId`로 두어 스크러버 대상에서 빠진다.

구현 중 잡은 것 둘:
- 구름 반경을 5.0으로 잡았더니 입자가 카메라 코앞까지 와서 거대한
  스프라이트로 화면을 덮었다. 3.8로 줄였다.
- 그래도 구름이 프레임을 넘쳐 노이즈로 보였다. 오프닝 동안 카메라를
  10.2에서 6.3으로 밀고 들어오게 해서 구름 전체가 프레임에 들어오게 했다.
- 거리 감쇠는 형상 크기(반경 1.5)에 맞춰져 있어 멀리서 오는 입자를 전부
  배경색으로 지워버렸다. `uFogAmount`를 오프닝 동안 0.30에서 0.88로 올린다.

### 자동 슬로우모션

가장 볼 만한 구간은 입자가 날고 있는 중간인데 등속으로 두면 1초 남짓에
지나간다. 진행률에 따른 배속 `rateAt(t)`로 가운데만 늦춘다(최저 0.34배).
양 끝에서 1배로 돌아오므로 정착이 굼떠 보이지 않는다. 기준 길이는 2.4초에서
2.0초로 줄였다 — 슬로우모션이 실제 길이를 늘리기 때문이다.

### 커서 반경 조절

반발 반경이 고정 0.55라 너무 컸다. 슬라이더로 0.08~0.75에서 조절하고
기본값을 0.22로 낮췄다. 밀려나는 최대 거리도 반경에 비례시킨다 — 고정
상한을 쓰면 반경을 줄여도 한 번 밀린 입자가 똑같이 멀리 날아가 조절이
안 되는 느낌이 든다.

**부수적으로 고친 것**: 패널은 세로 스크롤이 되는데, 휠로 스크롤하다
슬라이더 위를 지나가면 브라우저가 스크롤 대신 슬라이더 값을 바꿔버린다.
두 슬라이더 모두 `wheel`을 막았다.

## 이번 범위 밖

사용자가 제외했다.
